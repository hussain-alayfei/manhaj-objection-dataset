# التشغيل والإصدار

## الحدود المثبتة

تطبيق داخلي عربي لمراجعي المشروع، بمصادقة رموز منفردة، لا حسابات عامة. النسخة المستضافة تعمل على Vercel مع Supabase (انظر [دليل النشر](deployment.md)). مع `LLM_PROVIDER=openai` تُرسل مقتطفات الكتاب (القواعد والأمثلة المسترجعة ونص الشبهة) إلى OpenAI مع `store=False`، وتُرسل نصوص الحقول إلى نموذج التضمين؛ والاستخراج الآلي من سطر الأوامر يرسل جميع المقاطع. استخدم Ollama محليًا إن كانت سياسة البيانات تقتضي بقاء النص على الجهاز. الإدخال والاستخراج الآلي وكشف التكرار والعائلات والبحث الخارجي تعمل من سطر الأوامر فقط في النسخة المستضافة (حد 300 ثانية و4.5 MB لكل طلب).

خادم FastAPI يعيد أخطاء التحقق و409 للإصدارات المتعارضة، ويضيف CSP وحظر origin مختلف وعدم التخزين المؤقت. لا تُدرج النصوص كـHTML: الواجهة تهرب بيانات المصدر والتحليل. PDF والبيانات والعمليات كلها خلف المصادقة؛ الصفحة الفارغة وhealth فقط عامتان.

## قبل إتاحة الخدمة خارج جهاز واحد

- شغّل اختبارات CI على PostgreSQL/pgvector الفعلي، ثم اختبار ترقية واستعادة.
- استخدم TLS وحدود معدل الطلب وحجم الجسم (100 MB أو أقل) عند الوكيل؛ لا تكشف منفذ PostgreSQL للعامة.
- خصص حساب هجرة يملك DDL وحساب تطبيق بأقل امتيازات. لا يستخدم حساب التطبيق صلاحيات مالك قاعدة الإنتاج.
- احفظ الأسرار خارج Git ودوّر رموز المراجعين عند تغير صلاحياتهم.
- ضع ملفات PDF غير الموثوقة في عامل إدخال معزول محدود الذاكرة والوقت قبل توسيع قبول ملفات من خارج الفريق. V1 يفترض مصادر يرفعها مشغل داخلي موثوق؛ الإدخال متزامن وقد يستغرق دقائق.
- راقب health وأخطاء الاستخراج وفشل النماذج وعمليات التصدير؛ لا تسجل الرموز أو النصوص الحساسة في سجلات الوصول.
- انسخ PostgreSQL وملفات data/source وتهيئة النماذج احتياطيًا، وافحص الاستعادة إلى بيئة منفصلة. خطة Supabase المجانية بلا نسخ قابلة للتنزيل: شغّل `npx supabase db dump --linked -f backups/<date>.sql` أسبوعيًا، والمشروع المجاني يتوقف بعد 7 أيام بلا نشاط.
- عيّن حدًا شهريًا للإنفاق في OpenAI و`DIAGNOSE_DAILY_LIMIT` لكل مراجع.

المرجع الرسمي لخيارات النسخ الاحتياطي: [PostgreSQL backup and restore](https://www.postgresql.org/docs/17/backup.html).

## الأداء والموثوقية

مناسب لحجم V1: BM25 يفحص سجلات معتمدة في الذاكرة، والمتجهات في pgvector (وفي SQLite حساب cosine محلي). فهرس HNSW موجود؛ الاستعلام الحالي دقيق فوق معرفات مرشحين مؤهلين، ولا يدعي تحسين بحث تقريبي واسع النطاق. إعادة ترتيب lexical مستقلة عن التضمين؛ يمكن استبدالها لاحقًا بمصنف إعادة ترتيب عربي بعد تقييمه.

المقترحات والعائلات لا تغير الاعتماد. التدريب يستخدم إصدارًا محددًا في بيان تقسيم؛ الإلغاء بعد تصدير ملف لا يستطيع سحب النسخة التي نزلت سابقًا، لذا راجع سجل training_exports واسحب/أعد إصدار المجموعات المتأثرة عند إلغاء اعتماد مصدر أو قاعدة.

التصدير من الواجهة يُبنى في الذاكرة ويُنزّل مباشرة مع بصمته في ترويسة `X-Content-SHA256`. التصدير من سطر الأوامر يكتب ملفًا مؤقتًا ثم يستبدله ذريًا داخل معاملة تسجيل التصدير. فشل إنهاء المعاملة بعد كتابة الملف قد يترك ملفًا يتيمًا؛ لا توزع الملفات التي لا تحمل سجل training_exports مطابقًا وبصمة صحيحة. المستهلك الإنتاجي ينبغي أن يستهلك بيان التصدير وبصمته، لا مجلد الملفات عشوائيًا.

## أوامر التشخيص

```sh
python -m src.cli --help
python scripts/verify_dataset.py
pytest -q
```

عدم وجود نموذج/قاعدة معتمدة حالة امتناع متوقعة، لا إخفاق يتجاوز بإجبار التصنيف. خطأ بُعد المتجه يستلزم توافق النموذج والهجرة. خطأ 409 يستلزم إعادة فتح أحدث نسخة، ولا يعالج بتجاوز رقم الإصدار.
